# Apple Music Linux 1.4.2 — current account status and keyboard sign-in

Local patch build; not published upstream.

After a successful DRM login, Settings could show “Not signed in” alongside FairPlay ready and Session valid. The account section read an old preloaded snapshot while status rows refreshed. Settings now fetches current authorization on every open and refreshes the account section when background restoration changes sign-in state.

Enter in Apple ID moves focus to the password, Enter in the password submits sign-in, and Enter in the verification field submits its code. Pending requests disable duplicate submission.

The user's installed 1.4.1 login reached authenticated FairPlay and a valid session. Two isolated engine restarts using a private copy of the successful saved account restored authentication and CBCS capability without another password or code. Real Electron tests exercise all three Enter actions. See [the validation report](../verification/auth/README.md).

Explicit quit completes after web storage, local state and engine cleanup, so web-player unload handlers cannot leave a stopped-engine window blocking the next launch.

The installer preserves account files and web storage. Actual lossless playback, further account variants, third-party authorization and iPhone QR/passkeys remain to be qualified.
